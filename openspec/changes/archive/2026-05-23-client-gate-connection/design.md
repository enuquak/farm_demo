## Context

本项目是类星露谷物语多人联机农场游戏的网络基础设施。当前处于项目初期，需要建立客户端与服务器之间的通信架构。

整体服务器架构采用网关模式：
- **Gate**: 网关服务器，客户端直接连接的入口
- **Game**: 游戏逻辑服务器（后续开发）
- **DBManager**: 数据库管理器（后续开发）
- **Database**: SQLite 数据库（后续开发）

本次仅实现 Gate 和客户端连接模块。

## Goals / Non-Goals

**Goals:**
- 建立稳定的 TCP 长连接通信
- 实现跨平台网络库（libevent）
- 定义清晰的 Protobuf 消息协议
- 实现基础心跳机制
- 为后续 Game 服务器集成预留接口

**Non-Goals:**
- 不实现游戏逻辑（移动、交互、背包等）
- 不实现 Game 服务器
- 不实现数据库持久化
- 不实现完整的登录认证流程
- 不处理复杂的路由转发逻辑

## Decisions

### 1. 网络库选择：libevent

**决策**: 使用 libevent 作为跨平台网络库

**理由**:
- 成熟稳定，广泛用于游戏服务器开发
- API 简洁直观，学习成本低
- 跨平台支持好（Linux epoll、Windows IOCP、macOS kqueue）
- 社区活跃，文档完善

**备选方案**:
- libuv: 更偏 Node.js 生态，API 风格不太适合 C++ 游戏服务器
- asio: 现代 C++ 风格，但学习曲线较陡

### 2. 消息协议：Protobuf + 长度前缀

**决策**: 使用 Protobuf 序列化消息，采用 4 字节长度前缀解决粘包问题

**消息格式**:
```
┌──────────────┬──────────────┬──────────────────┐
│ Length (4B)  │ MsgID (4B)   │ Payload (变长)    │
│ 网络字节序   │ 消息类型ID    │ Protobuf 编码    │
└──────────────┴──────────────┴──────────────────┘
```

**理由**:
- Protobuf 跨语言支持好（C++/Python）
- 长度前缀是最常用的 TCP 粘包解决方案
- MsgID 用于消息路由和分发

### 3. 心跳机制

**决策**: 客户端定期发送心跳包，服务器超时未收到则断开连接

**参数**:
- 心跳间隔: 5 秒
- 超时断开: 15 秒（3 次心跳未收到）

**理由**:
- 及时检测死连接
- 保持 NAT 映射
- 参数可根据实际网络环境调整

### 4. 客户端架构：独立网络线程

**决策**: 客户端使用独立线程处理网络 IO，与 PyGame 主循环解耦

**架构**:
```
┌─────────────────────────────────────┐
│          PyGame 主循环              │
│  ┌─────────────┐ ┌─────────────┐   │
│  │ 事件处理     │ │ 渲染更新     │   │
│  └──────┬──────┘ └──────▲──────┘   │
│         │               │          │
│  ┌──────▼───────────────┴──────┐   │
│  │      消息队列 (线程安全)      │   │
│  └──────▲───────────────┬──────┘   │
│         │               │          │
│  ┌──────┴──────┐        │          │
│  │ 网络线程     │        │          │
│  │ - 收发消息   │        │          │
│  │ - 心跳维持   │        │          │
│  └─────────────┘        │          │
└─────────────────────────────────────┘
```

**理由**:
- 避免网络 IO 阻塞游戏渲染
- 线程安全队列保证数据一致性
- 网络异常不影响游戏主循环

### 5. Gate 会话管理

**决策**: Gate 维护 Session 对象，存储连接状态和玩家信息

**Session 数据**:
- 连接 fd
- 玩家 ID（登录后）
- 连接时间
- 最后心跳时间
- 当前所在 Game（后续使用）

**理由**:
- 集中管理连接状态
- 便于心跳检测和连接清理
- 为后续路由转发提供依据

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|---------|
| libevent 在 Windows 上性能不如 Linux | 开发阶段可接受，生产环境部署到 Linux |
| 心跳包增加网络开销 | 心跳消息体积小（~20 字节），可接受 |
| 独立网络线程增加复杂度 | 使用线程安全队列，明确的线程边界 |
| Protobuf 增加序列化开销 | 对于游戏消息频率，开销可忽略 |

## Migration Plan

这是全新项目，无需迁移计划。

**部署步骤**:
1. 编译 Gate 服务器（需安装 libevent、protobuf）
2. 启动 Gate 服务器，监听指定端口
3. 启动 Python 客户端，连接 Gate

**回滚策略**: 不适用（全新项目）
